# 04 · 附件下载

用户明确说过：**「有一个非常重要的内容，就是要下载页面里的文件」**。这一节记录附件的识别、规模、直链机制和命令行用法。

## 识别附件链接：一个隐蔽的坑

第一版附件数永远是 **0**。原因是官网把**文件名藏在 query string** 里：

```
https://hbj.huzhou.gov.cn/api-gateway/jpaas-web-server/front/document/download
    ?fileUrl=YW5UzzlvCwcM%2FNHHX%2FtT6HPkKRydEHVtmMoD7H9KH2x...
    &fileName=%E6%B9%96%E5%B7%9E%E7%9B%9B%E7%A5%A5...%E6%8A%A5%E5%91%8A%E8%A1%A8.rar
```

所以这种写法会全部漏判：

```python
url.split('?')[0].endswith('.zip')   # ← 错
```

正确写法（`monitor.py` 的 `looks_like_file()` 和 `worker/src/index.js` 的 `looksLikeFile()` 都要有）：

```python
def looks_like_file(url):
    if not url: return False
    low = url.lower()
    if any(low.split("?")[0].endswith(e) for e in ATTACH_EXT): return True
    m = re.search(r"[?&]filename=([^&]+)", low)
    return bool(m and any(m.group(1).endswith(e) for e in ATTACH_EXT))
```

修好之后：附件数 **0 → 81**，分布在 **59 条**公告里。

## 规模（229 条公告的统计）

| 指标 | 值 |
|---|---|
| 带附件的公告 | 59 / 229 |
| 附件总数 | 81 |
| 总体积 | **约 1 GB** |
| 最大单文件 | 137.5 MB |
| 常见体积 | 20~40 MB |
| 最小 | 349 KB |
| 格式 | `.rar` / `.zip` / `.pdf` / `.doc(x)` |

**结论：Worker 绝不下载附件本体。** 128 MB 内存上限、25 MB KV 单值上限、1 GB 命名空间总量，三个都会爆。分工是 Worker 只存元数据+链接，本体交给本地脚本。

## 网关 → OSS 直链（两跳）

```
① 网关
   https://hbj.huzhou.gov.cn/api-gateway/jpaas-web-server/front/document/download?fileUrl=<密文>
   ↓ 302
② 中转
   https://hbj.huzhou.gov.cn/cms_files/filemanager/1572864/attach/20269/<hash>.rar
   ↓ 301
③ OSS 直链
   https://zjjcmspublicnew.oss-cn-hangzhou-zwynet-d01-a.internet.cloud.zj.gov.cn/cms_files/filemanager/.../<hash>.rar?fileName=<文件名>
```

**关键事实**：

- `fileUrl` 是**服务端加密的**，base64 解出来是 **128 字节密文**，**算不出真实路径**
- 原始详情页 HTML 里搜不到 `zjjcmspublicnew` / `attach/`，直链**只在重定向之后才出现**
- 所以只能跟随重定向拿：`Range: bytes=0-0` + `allow_redirects=True`，既不下载内容又能拿到最终 URL 和体积

**OSS 直链本身是公开可读的**，实测：

| 项 | 结果 |
|---|---|
| HTTP | 200 |
| Content-Type | `application/octet-stream` |
| Content-Length | 39,910,780（38.1 MB，以湖州盛祥研磨那个 .rar 为例） |
| 文件头 | `Rar!\x1a\x07\x01\x00` |
| 需要 Referer | **否** |
| 需要鉴权 | **否**（无签名参数） |
| 响应耗时 | 约 0.2 秒 |

## 命令行

```bash
# 看看有哪些附件、多大（只探测不下载）
python3 tools/download.py --dry-run

# 按单位下载
python3 tools/download.py --unit 南浔分局

# 按关键词（会搜文件名）过滤
python3 tools/download.py --keyword 电梯

# 限制单个体积、限制个数、并发
python3 tools/download.py --max-size 50mb --limit 10 --workers 8

# 解析全部附件的 OSS 直链 → files/direct_links.csv
python3 tools/download.py --resolve
```

其他参数：`--since`（按日期）、`--max-size`、`--workers`。

支持**断点续传**和**跳过已存在**的文件，重跑安全。

## 输出

```
files/
  <日期>_<单位>/<项目名>/<文件名>      # 附件本体
  manifest.csv                       # 已下载清单
  direct_links.csv                   # --resolve 产出的直链清单
```

`direct_links.csv` 列：公告日期 / 发布单位 / 项目名称 / 建设单位 / 文件名 / 大小 / **OSS直链** / 网关地址。

已跑完全部 81 个附件，成功率 81/81。拿到这份清单后可以脱离脚本批量拉取，例如转成 `aria2 -i` 的输入文件直接开 1 GB 全量下载。

> 注意：`files/` 在 `.gitignore` 里（`data/`、`reports/`、`kv-bulk.json` 也一样），属于可被本地重新生成的产物，不进仓库。
